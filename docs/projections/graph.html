What this view is

The system graph is the one model the rest is generated from (Chapter 3). Each node here is a function of the cache, with the clauses it serves, the effects it may have, its proved worst case and the obligations proved about it; each edge is a call. The first view groups the 146 nodes into subsystems, with the number of calls between them; below it, every node, with links both ways along its edges. The grouping is the only hand-made part: it is a rule on function names in tools/projections.py.

Subsystems and the calls between them

Every node

Worst case is the proved bound on instructions for one call, from the cost plane; for boot functions that wait on hardware it counts the longest wait the loop bounds allow. A function inlined after proof has no code, stack or bound of its own: its instructions are counted in its callers'. Effects are those the function may have, all within N-8; 20 functions are proved pure. Most common effects: cpu.clock (37), ena.mmio (31), firmware.tables (21), nvme.mmio (15), firmware.call (14), uart.io (10).
