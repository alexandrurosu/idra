Differential test

20,000 generated lines, including deeply nested expressions, overflow edges, corrupted input and over-long lines, fed to the running image over its serial port. Results: 9,255 values, 7,323 syntax errors, 3,293 overflows, 109 divisions by zero. 0 mismatches against the reference, in 51.4 seconds of emulation.

Checked against Arm's own specification

QEMU is an emulator someone wrote by hand. Phase 2 runs the same image, byte for byte, on Arm's machine-readable A-profile architecture specification: the Armv9.4-A Sail model, compiled to an executable. Around it sits only what QEMU's virt machine provides outside the instruction set: a PL011 serial port, PSCI power-off, and the firmware's hand-off to EL1. Instruction semantics come from the specification alone.

What is still trusted

Checker and Z3

Proofs are only as sound as the symbolic executor and the solver. Both are small enough to audit; neither is itself verified.

Backend

Proofs cover the IR, but the machine runs bytes. Encodings are cross-checked with LLVM and behaviour is tested on Arm's specification. That is testing, not proof: translation validation, proving each function's machine code equivalent to its IR, is the next step.

Firmware and platform

Power-off and the serial port are platform services: QEMU's on one machine, a small board model of the same devices around the specification on the other. The port address is fixed for QEMU's virt machine; reading it from the device tree comes with cloud hardware in Phase 3.
